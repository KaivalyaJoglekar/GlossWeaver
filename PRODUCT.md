# GlossWeaver product context

## Register

product

## Users and purpose

The project author and reviewers test custom telegraphic/incomplete text and inspect reconstruction experiments. Primary workflow: enter text, choose an available model, reconstruct, inspect output, and compare session runs. The research application includes ASL gloss output; ASL itself has complete grammar.

## Confirmed direction

The user chose a dark research workbench with side-by-side reconstruction, clear model status, session history and benchmark results. Preserve the existing indigo identity and use clear, factual language.

## Design principles

- Put custom text testing first.
- Identify the model and whether trained weights are available.
- Separate grammatical-feature predictions from semantic confidence.
- Show actual benchmark scope and errors.
- Keep session history local to the current page session unless explicitly exported.

## Accessibility and inclusion

Use native labeled controls, keyboard navigation, visible focus, readable contrast, live status announcements, reduced-motion support and responsive stacking. No specific certification was requested.

## Latest direction

The user requested a more minimal interface and direct visibility into dataset locations. Keep the dark theme, shorten the primary workflow, collapse secondary detail and show dataset manifests in a dedicated tab.

## GlossWeaver 2.0 brief

The latest explicit request supersedes the compact indigo revision: deliver a dark graphite/cyan reconstruction laboratory with an Overview, full Studio, real model comparison, saved research exploration, model library, datasets, and Settings/About. Preserve actual inference, historical artifacts, and session history. No fabricated scores, confidence, or unavailable checkpoint substitutions. Semantic checks are advisory and authentic ASL remains distinct from synthetic corrupted English.

## Current visual refinement

Use true black for the dark theme and refine the existing design using emil-design-eng and design-taste-frontend. Preserve information architecture, reconstruction functionality, and research integrity. Apply design-taste guidance to the Overview composition; use interaction engineering for the product workbench.
